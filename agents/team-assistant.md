# Помощник команды

При передаче смены дежурный открывает в своём проекте карточку «Помощник команды». Агент превращает заметки дежурного в сводку для следующей смены. Версию шаблона `agent-support-1-1`, модель и инструкцию задаёт поставщик. [Карточка и параметры формы](../examples/agent-offering.yaml)

## Заказ в проекте

Сотрудник выбирает обязательный `summaryFormat` — `brief` для краткой сводки или `checklist` для списка действий. Целое число `itemLimit` задаёт максимум пунктов от 1 до 10, по умолчанию 5. При необходимости сотрудник подключает базы знаний, доступные ему и проекту. Сервер IDP берёт `projectId` из контекста проекта, `requesterId` из проверенной сессии сотрудника, версию и тип ресурса из карточки.

По кнопке «Создать агента» IDP отправляет служебный запрос на `POST /orders` по базовому пути `/v2`. В этом примере сотрудник выбрал список до трёх пунктов, а сервер IDP передаёт заголовок `Idempotency-Key: shift-demo-01`.

```json
{
  "projectId": "team-demo",
  "requesterId": "user-demo",
  "offeringId": "agent-support-1-1",
  "resourceType": "agent",
  "parameters": {"summaryFormat": "checklist", "itemLimit": 3}
}
```

При выборе баз IDP добавляет их идентификаторы в `knowledgeBaseIds`. Одно действие создаёт один заказ. После потери ответа IDP повторяет сохранённое тело с тем же ключом. Первый приём даёт `202`, повтор принятого заказа — `200` с прежним `orderId`. [Контракт заказов](../openapi.yaml)

## Выдача и первый диалог

Поставщик публикует версию в GitLab Release. По заказу экземпляр автоматически разворачивается из этого релиза в Kubernetes IDP. IDP читает `GET /orders/{orderId}`. Пока поставщик готовит диалог, заказ остаётся в `in_progress`. Для `succeeded` инициатору должен быть доступен чат, агент должен ответить на контрольный запрос с настройками заказа, а поиск по подключённым базам — работать с учётом прав. Тогда IDP показывает «Открыть агента» со ссылкой из `resourceRef.url`. При `failed` сотрудник видит причину ошибки. [Сценарий интеграции](../README.md)

В чате сотрудник отправляет заметку «В 18:00 проверить очередь „Ирис“. После проверки сообщить результат группе „Маяк“». По этим вымышленным данным агент возвращает два действия.

- [ ] В 18:00 проверить очередь «Ирис».
- [ ] Сообщить результат группе «Маяк» после проверки.
