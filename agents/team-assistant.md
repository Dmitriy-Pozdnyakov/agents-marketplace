# Помощник команды

При передаче смены дежурный открывает в своём проекте карточку «Помощник команды». Агент превращает заметки дежурного в сводку для следующей смены. Версию шаблона `agent-support-1-1`, модель и инструкцию задаёт поставщик. [Карточка и параметры формы](../examples/agent-offering.yaml)

## Заказ в проекте

Сотрудник выбирает обязательный `summaryFormat` — `brief` для краткой сводки или `checklist` для списка действий. Целое число `itemLimit` задаёт максимум пунктов от 1 до 10, по умолчанию 5. При необходимости сотрудник подключает базы знаний, доступные ему и проекту. Сервер IDP берёт `projectId` из контекста проекта, идентификатор инициатора из проверенной сессии сотрудника, версию и тип ресурса из карточки.

По кнопке «Создать агента» IDP сохраняет собственный заказ, связывает его с экземпляром в проекте и передаёт исполнителю конфигурацию. В примере сотрудник выбрал список до трёх пунктов.

```json
{
  "projectId": "team-checkout",
  "offeringId": "agent-support-1-1",
  "parameters": {"summaryFormat": "checklist", "itemLimit": 3}
}
```

При выборе баз IDP добавляет их идентификаторы в `knowledgeBaseIds` и проверяет право сотрудника и проекта на каждую базу. Повтор того же действия восстанавливает сохранённый заказ и существующее размещение.

## Выдача и первый диалог

Поставщик публикует версию в GitLab. Исполнитель IDP устанавливает закреплённый релиз в Kubernetes-кластере IDP. Для выдачи инициатору должен быть доступен чат, агент должен ответить на контрольный запрос с выбранными настройками, а поиск по подключённым базам — учитывать права. По результату проверки IDP показывает «Открыть агента» со ссылкой из своего заказа либо причину ошибки. [Общая спецификация](../README.md)

В чате сотрудник отправляет заметку «В 18:00 проверить очередь „Ирис“. После проверки сообщить результат группе „Маяк“». По этим вымышленным данным агент возвращает два действия.

- [ ] В 18:00 проверить очередь «Ирис».
- [ ] Сообщить результат группе «Маяк» после проверки.
